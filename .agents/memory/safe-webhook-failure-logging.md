---
name: Safe webhook failure logging
description: Privacy boundary for structured operational logs generated by webhook failures.
---

Webhook failure logs must use a fixed allowlist of reason codes and fixed error-class categories. Do not log arbitrary exception messages or `Error.name` values, even after character filtering.

**Why:** Exception-controlled text can contain credentials, customer data, or payload-derived identifiers. Character sanitization does not make allowed-looking token strings safe.

**How to apply:** For payment and authentication webhooks, log safe event metadata plus an allowlisted reason code. Use a constant `Error`/`non_error` discriminator if classification is needed, and keep the original exception out of the structured record.
